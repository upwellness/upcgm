# UP CGM Analyser

เครื่องมือของ **โค้ช UP Wellness** สำหรับอ่านไฟล์เครื่องวัดน้ำตาลต่อเนื่อง (CGM) แล้วคุยกับเคส
พร้อมออกใบสรุป 1 หน้า A4 เป็นรูปภาพให้เคสเอากลับไปได้

โค้ชเข้าใช้งานด้วย **รหัสที่ทีมออกให้** — ไม่ต้องมี API key ของตัวเอง แค่อัปโหลดไฟล์ Excel/CSV
ที่ดาวน์โหลดจากแอปเครื่องวัด

---

## ใช้งานยังไง

1. เปิดเว็บ → กรอกรหัสเข้าใช้งาน
2. ลากไฟล์ `.xlsx`/`.csv` จากแอปเครื่องวัดเข้ามา (ไม่เกิน 5 MB)
3. ตอบคำถามข้อเดียว: เคสใช้ยาลดน้ำตาลอยู่ไหม (เปลี่ยนวิธีอ่านช่วงน้ำตาลต่ำ)
4. เลือกช่วงเวลา: 30/14/7/3 วัน · 24/12/6/3 ชั่วโมง · หรือกำหนดเอง
5. บันทึกมื้ออาหารเป็น marker → เห็นการตอบสนองหลังมื้อ (ขึ้นเท่าไร กี่นาทีถึงสูงสุด กี่นาทีกลับที่เดิม)
   · กดดูค่าที่ **1 / 2 / 3 ชั่วโมง** หลังมื้อได้ · บันทึกแล้วจดจำอัตโนมัติ ไม่ต้องกดเซฟ
6. กด **สร้างใบสรุปให้เคส** → ได้ PNG ขนาด A4 (1588 × 2246 px) หรือสั่งพิมพ์เป็น PDF

## ทำไมออกแบบแบบนี้

**การตีความอยู่ฝั่งเซิร์ฟเวอร์ทั้งหมด** — เกณฑ์, ขอบเขตแต่ละช่วง, กฎตัดค่าที่เซนเซอร์หลุด และ
กฎแปลงตัวเลขเป็นประโยค อยู่ใน `server/` และไม่เคยถูกส่งไปที่เบราว์เซอร์ ตัวอ่านไฟล์ (SheetJS
140 KB) ก็อยู่ฝั่งเซิร์ฟเวอร์ด้วย ทำให้ bundle ฝั่ง client เหลือ ~120 KB

**ไม่เก็บข้อมูลสุขภาพ** — ไฟล์ถูกอ่านจาก request stream ไม่เขียนลงดิสก์ ไม่มีฐานข้อมูล
มื้ออาหารที่โค้ชบันทึกเก็บใน `localStorage` ของเครื่องโค้ชเท่านั้น (กดบันทึกเป็นไฟล์เพื่อย้ายเครื่องได้)

**ทุกเกณฑ์ประกาศที่มา** — `consensus` = ฉันทามติสากล (Battelino 2019 / ADA) · `house` = ทีมกำหนดเอง
บนหน้าจอจะมีป้าย “เกณฑ์ของเราเอง” กำกับไว้ ห้ามเอาเกณฑ์ของเราไปอ้างเป็นมาตรฐานสากล

**ตัวเลขที่เชื่อถือไม่ได้ จะไม่แสดง** — ช่วง 3 ชั่วโมงไม่แสดง % เวลา / CV / GMI เพราะตัวเลขพวกนี้
บนช่วงสั้นหน้าตาเหมือนของจริงเป๊ะ แต่ไม่มีความหมาย (`gateForWindow` ใน `server/cgm/thresholds.ts`)

**รูปร่างกราฟหลังมื้อ = พุ่ง / กว้าง / ค้าง / ตก** (`server/cgm/patterns.ts`) — คำทั้งสี่เป็นคำที่ทีมตั้งขึ้นเอง
เพื่อสอนให้จำง่าย **ไม่ใช่ศัพท์ทางการแพทย์** และยังไม่มีมาตรฐานสากลที่จัดกลุ่มรูปกราฟแบบนี้ เกณฑ์ทั้งหมดจึงเป็น
`house` และหน้าจอกับใบสรุปต้องติดป้ายบอกเสมอ · กฎที่ต้องรักษาไว้:
- มื้อจริงมักเข้าหลายแบบพร้อมกัน — เลือก **แบบที่ต้องแก้ก่อน** เป็นหลัก แล้วรายงานที่เหลือเป็น `also`
  ลำดับความสำคัญ: ตก → ค้าง → พุ่ง → กว้าง (ตกมาก่อนเพราะเป็นข้อเดียวที่มีผลด้านความปลอดภัย)
- **แยก "ข้อมูลไม่พอ" ออกจาก "ไม่เข้าเกณฑ์แบบไหนเลย"** ให้ชัด — รวมเป็นตัวเลขเดียวเมื่อไร โค้ชจะอ่านว่า
  เครื่องมือพัง ทั้งที่จริงคืออ่านได้ชัดเจนแล้วว่ามันอยู่กลาง ๆ
- **ไม่ฟันธงจากมื้อเดียวสองมื้อ** — ต้องมีอย่างน้อย 3 มื้อที่อ่านได้จึงจะบอกว่าเป็นแพตเทิร์นประจำ
- **"เรียบ" ไม่มีวันเป็นแบบที่ต้องแก้** — มื้อที่กลับลงมาที่เดิมคือมื้อที่ควรทำซ้ำ
- เจอ "ตก" ในเคสที่ใช้ยาลดน้ำตาล = **ส่งแพทย์ผู้สั่งยา** ไม่ใช่เรื่องที่ปรับด้วยเมนู

**ใบสรุปให้เคสไม่มีชื่อสินค้าและไม่มีราคา** — เอกสารที่คนไข้ถือไปหาหมอต้องไม่เป็นใบขายของ

## Environment

| ตัวแปร | จำเป็น | ใช้ทำอะไร |
|---|---|---|
| `UPCGM_SESSION_SECRET` | ✅ | HMAC ของ session cookie · อย่างน้อย 32 ตัวอักษร |
| `UPCGM_PASSCODES` | ✅ | รายการรหัสเข้าใช้งาน `label:salt:hash[:YYYY-MM-DD]` คั่นด้วย comma |
| `UPCGM_GEMINI_API_KEY` | – | คีย์กลางสำหรับทั้งระบบ · **ปกติไม่ต้องใส่** — โค้ชใส่คีย์ของตัวเองที่หน้า `/config` |
| `UPCGM_AI_MODEL` | – | โมเดลสำรองเมื่อโค้ชไม่ได้เลือก · ค่าเริ่มต้น `gemini-flash-latest` |
| `UPCGM_AI_DISABLED` | – | ตั้ง `1` เพื่อปิดการเรียก AI ทันทีโดยไม่ต้องลบ key |

### ออกรหัสให้โค้ชคนใหม่

```bash
node scripts/passcode.mjs coach-jin 2027-01-31
```

จะได้ 2 อย่าง: **รหัสที่ส่งให้โค้ช** และ **บรรทัด entry** ที่ต้องเอาไปต่อท้าย `UPCGM_PASSCODES`
(คั่นด้วย comma) แล้ว redeploy — รหัสเก็บเป็น scrypt hash ไม่เก็บตัวจริง และหมดอายุแยกกันได้
รหัสรั่วหนึ่งใบ ลบเฉพาะใบนั้น ไม่กระทบคนอื่น

```bash
# สร้าง secret
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Golden fixtures

ไฟล์จริงของคนไข้ **ไม่ commit** (`tests/fixtures/*.xlsx` อยู่ใน `.gitignore`)
เทสที่ใช้ไฟล์จริงจะ skip ตัวเองถ้าไม่มีไฟล์ ทำให้ clone ใหม่ก็ยังรันผ่าน
ถ้าจะรัน golden regression ให้วางไฟล์ชื่อ `golden-normal.xlsx`, `golden-high.xlsx`,
`golden-floorrun.xlsx` ใน `tests/fixtures/`

## ข้อควรระวังที่เจอมาแล้ว

- **`new Date("2026-07-19 15:19")`** — Safari คืน Invalid Date, engine อื่นตีความเป็น local time
  แล้ว AGP เลื่อนไปทั้งกราฟแบบไม่มี error ใช้ `coerceTime` ใน `lib/time.ts` เท่านั้น
- **serial ของ Excel ไม่ตรงนาทีเป๊ะ** — SheetJS เองเขียนเพี้ยนได้ถึง 48 วินาทีเมื่อรันใน timezone
  สุดขั้ว `fromSerial` จึงปัดเข้าหานาทีที่ใกล้ที่สุด ไม่ตัดทิ้ง
- **ค่า 36 มก./ดล. ในไฟล์ Ottai** = "36 หรือต่ำกว่า" ไม่ใช่ 36 พอดี ถ้าลงมาถึงในก้าวเดียว
  (เกิน 25 มก./ดล. ต่อ 5 นาที) หรือค้างเกิน 2 ชั่วโมง = เซนเซอร์หลุด ไม่ใช่ภาวะน้ำตาลต่ำ
  ไฟล์จริงหนึ่งไฟล์รายงาน "ต่ำรุนแรง 9 ชั่วโมง" ถ้าไม่แยกส่วนนี้
- **`import 'server-only'`** พังใน vitest — ใช้ข้อตกลงเรื่องโฟลเดอร์แทน
- **html2canvas สืบทอด CSS transform ของ ancestor** — ต้องปิด transform ของ preview ก่อน capture
  ไม่งั้นได้รูปกว้าง 686px แทน 1588px
- **html2canvas จัด text ใน `display:grid` ไม่ได้** — ตัวเลขในวงกลมหลุดออกไปมุมซ้ายบน
  ใช้ inline SVG แทนถ้าต้องการข้อความกลางวงกลม
- **SheetJS ที่ npm ค้างอยู่ที่ 0.18.5** ซึ่งมีช่องโหว่ Prototype Pollution + ReDoS และ **ไม่มี fix บน npm**
  เวอร์ชันที่แก้แล้วอยู่บน distribution ของ SheetJS เอง → `package.json` จึงชี้ไปที่
  `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` **ข้อแลกเปลี่ยน:** ถ้า CDN ล่ม build จะพัง
  (แก้ได้ด้วยการ vendor ไฟล์ .tgz เข้า repo ถ้าอยากตัดความเสี่ยงนี้) · ช่องโหว่ 2 ตัวนี้เข้าถึงได้จริง
  เพราะเรา `XLSX.read` ไฟล์ที่ผู้ใช้อัปโหลดโดยตรง
- **`overrides` ใน package.json จำเป็น** — Next มี postcss กับ sharp เป็น nested dep ที่ยังมีช่องโหว่
  การ bump ตัวบนสุดไม่ถึง ต้อง override (npm ปฏิเสธ override ที่ค่าไม่ตรงกับ direct dependency)
- **Vercel middleware ห้าม import `node:crypto`** — แม้อยู่ใน branch ที่ไม่ทำงาน ก็ทำให้ build พัง
  จึงมี `session-edge.ts` แยกไว้ (มีเทสเทียบกับฝั่ง node ว่าตัดสินเหมือนกัน)
